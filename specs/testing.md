# Testing

This document defines how Arc parser and runtime behavior is inventoried for testing and how test cases are derived from that inventory. It exists so coverage is driven by the specs rather than by bug history: when a feature is added or changed, this document says what test cases it owes and where they belong.

The companion manifest `__tests__/COVERAGE.md` maps every inventory entry below to the tests that exercise it. A change that adds or alters spec behavior updates the inventory here, the manifest, and the tests in the same change.

## Coverage Model

Arc behavior is specified in three documents: [arc-scripts.md](./arc-scripts.md) defines the authored language, [arc-runtime-api.md](./arc-runtime-api.md) defines the host-facing protocol, and [internal-semantics.md](./internal-semantics.md) defines implementer-facing invariants. The inventory below decomposes those specs into **behavior entries** — individually testable rules, each with a stable id. An entry is the unit of coverage accounting: the manifest marks it covered, partially covered, or uncovered, naming the tests that prove it.

A behavior entry is not one test. Most entries expand into several required cases along two axes, and missed basics historically hide at the intersections.

### Contexts

An authored form keeps one meaning everywhere it is admitted, but each admission is a separate evaluation path in the runtime. The contexts are:

- the main action graph of a node body,
- a trigger body,
- a guard body,
- an effects body,
- an instruction `resolveWhen` / `deflectWhen` body,
- an `enterLoop` `resolveWhen` body,
- a `catchDeflection` body,
- an invoke body,
- a `$map` callback body,
- an owned child node,
- an imported arc.

The specs define which forms each context admits. A form's entry owes cases in every admitted context, and a rejection case in at least one context that does not admit it.

### Outcomes

Every case exercises the form to a definite outcome. The outcome families are:

- **resolves** — the happy path; the form completes and traversal continues,
- **blocks and resumes** — the form yields a brief and a later report resolves it, including across a fresh runtime after persistence,
- **unknown or needs-user** — the host cannot resolve; the form consumes or resurfaces per its rules,
- **invalid item** — the reported value fails validation; the item re-yields while the valid subset applies,
- **invalid report** — the report as a whole is rejected and the frontier re-yields,
- **deflects** — the form triggers deflection and propagation runs,
- **poisons** — authored error or host contract failure terminates the traversal.

### Required cases rule

For every behavior entry:

1. One resolving case per admitted context.
2. For forms involving host work, one blocked-and-resumed case, and the non-resolving outcomes the form's rules distinguish (unknown, needs-user, invalid item).
3. For typed or validated forms, one boundary case and one invalid case per validation rule.
4. For forms that write persistent state, one case proving the state round-trips through serialization onto a fresh runtime.
5. For forms with an authored rejection rule, one parse-time or validation rejection case per rule.

Cases 2–5 may live in one test when the scenario naturally covers them, but the manifest must name which entry cases a test proves.

## Adding or Changing a Feature

1. Write or update the owning spec section first ([internal-semantics.md](./internal-semantics.md) governs conflicts).
2. Add or update behavior entries below, one per new rule, keeping ids stable.
3. Expand each entry with the required cases rule and write the tests.
4. Update `__tests__/COVERAGE.md` in the same change.

When a test must change during a semantic change, first decide whether the old expectation exposed a real bug. Do not weaken a test to match implementation behavior unless the spec intentionally changed.

## Behavior Inventory

Ids are `area.slug`. The **Behavior** column states the rule and any entry-specific required cases beyond the standard rubric.

### Documents (`doc`)

| Id | Behavior |
| --- | --- |
| `doc.directive` | The first statement must be the `"arc"` directive; anything else is rejected. |
| `doc.multi-arcs` | Every root node declaration is an arc; multiple roots in one document register independently by identifier. After the `"arc"` directive, the document body admits only imports and root node declarations. A document-level cell declaration is rejected because cells must belong to a node. |
| `doc.arc-imports` | Arcs import by named import, optionally aliased; default arc imports and `export` syntax are rejected. |
| `doc.host-imports` | Host modules import as default imports from `host:*` sources; named host-module imports are rejected. A host-module alias cannot use a reserved Arc identifier, including primitive roots, semantic namespaces, action roots, target wrappers, and the scoped `args`, `returns`, and `span` namespaces. Authored source and public `Document` IR enforce the same reservation before expression validation. |
| `doc.comments` | Line and block comments are ignored in every source position. |
| `doc.validation` | Public `Document` IR validation rejects semantic invariants that parser output normally enforces, including finalization-only expressions outside their scopes, non-canonical `this.deflection.escaped(...)` targets, self-entry, target import mismatches, duplicate bindings, and node import visibility that does not correspond to a document import. Before semantic walking it rejects accessors, symbol and non-enumerable fields, sparse or decorated arrays, custom prototypes, cycles, and unsupported JavaScript values without invoking caller code. |
| `doc.numeric-validity` | Numeric source literals are finite independently of arithmetic: parser-wide preflight covers ordinary expressions, arrays, templates, host-call arguments, nested node/instruction host params, and `Dialog.lastTurns`, throwing the settled coded `Error` before contextual lowering. Non-mutating `validate(document)` covers hand-built and deserialized IR and reports the settled exact codes and canonical paths for non-finite values, legacy Source / IR `rangedInt`, malformed or misplaced `observeAs`, invalid operator families, malformed `numIsFinite`, invalid `Dialog.lastTurns` counts, and local/value expression-stratum violations. `Runtime.add` validates the raw graph, clones with numeric identity preserved, stamps and analyzes the private clone, captures its rewalk plan, and canonicalizes negative zero only after validation before collecting atomically. Required cases include special object-key paths and proof that validation never mutates the caller's document. |
| `doc.element-ids` | Element ids are structural and SEG-scoped: every statement (control flow included) and briefable expression gets its position-derived id, editing one SEG or if-branch shifts no ids outside it, and ids are node-relative. Stamping is idempotent and canonical (`parse` stamps its output, `Runtime.add` stamps its private clone so unstamped hand-built IR registers, `validate` reports non-canonical ids without mutating). Inherited `deflectWhen` copies stamp under the static `deflectWhen/` scope with per-owner brief qualification intact; anonymous-copy refs round-trip ids through ref encoding. |

### Spec System (`spec`)

| Id | Behavior |
| --- | --- |
| `spec.type-ownership` | Public value, spec, parser-IR, runtime-state, and host-interaction definitions are owned by their domain modules and compile through `arc/types`; parser IR and analysis contracts compile through `arc/parser`; runtime contracts compile through `arc/runtime`. Stored arrays and primitive observation/report arrays have distinct public carrier types. Internal producer evidence and judgments are not package exports. |
| `spec.representation` | TypeScript spec shapes are representational supersets. Semantic validation rejects invalid representable guarantees such as empty or duplicate Enum domains. Cell and channel arrays are one-level and admit a scalar or Artifact element guarantee; nested arrays, cursor, and Index are invalid in that position. Authored observation and initializer metadata remains outside `CellSpec`. |
| `spec.concrete-admission` | Concrete admission enforces Bool, Str, Enum membership, finite Num, non-negative-safe-integer Index, one-level arrays, Artifact carrier/path invariants, and dialog-cursor invariants. Array admission applies the element guarantee recursively and reports the first failing index. Every constrained runtime landing reapplies admission even after compatible static evidence. Observation reports apply it before observation-only constraints. |
| `spec.one-time-landing` | One-time landing coherence is directional over IR-independent site, exact-literal, boolean/string/numeric-carrier, Artifact/cursor/Index-provenance, recursive-array, empty-array, and absent facts. Each call returns compatible, incompatible, or unknown according to the destination; unknown is only that call's inability to prove either conclusion. Required cases cover every relation row and the same source receiving different answers from different consumers. |
| `spec.conditional-reduction` | A conditional landing rejects when any reachable branch is incompatible, otherwise defers when any branch is unknown, and accepts only when every branch is compatible. A dynamic branch contributes the result of judging absent source evidence. |
| `spec.reusable-compatibility` | Reusable provider-to-receiver compatibility accepts only when every value guaranteed by the provider is admitted by the receiver. It is directional, recurses through arrays, widens Index to Num and Enum to Str, and never defers a broader provider to a narrower receiver. |
| `spec.producer-provenance` | Producer evidence is derived on demand from original IR and lexical, signature, map, and host-module context. Values and pins carry no provenance. Artifact versus Struct meaning follows the producer even when carriers are structurally identical. An environment-free host call remains dynamic; under a definitive host environment, a declared result supplies site evidence and replay rederives it from the original action path. |
| `spec.operation-coherence` | Shared operation rules pair producer checks with immediate concrete admission and intrinsic result facts. Required coverage includes arithmetic, `Num.isFinite`, boolean positions, regex/string operands, comparison including Enum domains, interpolation, Artifact construction, arrays, exact literals, and dynamic producers. Array equality selects one scalar or Artifact element authority without inferring Artifact authority from carrier shape; only primitive arrays support whole-value interpolation. Arithmetic results supply numeric-carrier evidence rather than a Num guarantee. |
| `spec.runtime-initialization` | `Runtime.add` collects document-local valid private snapshots in any import order. `Runtime.init` resolves the complete prospective registry with lexical, signature, and map context; one structured `RuntimeRegistrationError` contains every independent missing-target, undeclared-key, and incompatible args/returns issue in canonical order without dependent cascades. Failure is atomic and leaves collection retryable. Success seals the registry and enables execution. |
| `spec.pin-replay` | A pin persists only a durable finite carrier. Restoration rejects a malformed or non-finite resolved pin before replay. If one operand pins before another blocks, restored evaluation derives evidence from the original producer and reapplies the enclosing arithmetic or comparison admission before operating. A completed top-level expression enters destination admission synchronously. |

### Host Modules (`host`, `runtime`)

| Id | Behavior |
| --- | --- |
| `host.module-spec` | A normalized `HostModuleSpec` is an exact plain-data namespace tree whose operations declare ordered required parameters and an optional existing `ChannelSpec` result. The public `hmd.define()` utility normalizes plain object namespaces and synchronous declaration functions: evaluated `hmd` marker defaults declare positional parameters, the returned final marker declares the result, and an undefined return omits it. Markers are capture-local and shape-opaque; recursive parameter arrays and tuples consume their captured children, while a result array admits one immediate scalar or Artifact element spec. Enum domains retain the existing spec invariants; nested arrays, tuples, semantic text, and other parameter-only markers cannot declare results; asynchronous declarations are rejected without leaving unobserved promise rejections. Declaration trees reject invalid members, `$`-prefixed names, accessors, symbols, custom prototypes, and cycles. The declaration and dispatch path use unsigiled operation names. |
| `runtime.host-module-spec` | A `Runtime` privately validates and clones its injected declaration registry and treats omission as an empty definitive registry. Environment-free analysis remains optimistic only where host evidence is absent. Definitive `Runtime.add` atomically resolves imported modules and action paths, enforces call-result presence, exact arity, host-argument one-time coherence, and every ordinary consumer of declared result evidence; `Runtime.init` separately owns complete-registry Arc import and reusable binding compatibility. Before emission, rendered call/effect arguments receive exact concrete parameter admission and an invalid effects batch emits nothing. After generic host-result sanitation, each reported value receives exact concrete result admission before pin hydration; explicit top-level unset is independent of the result spec, invalid items re-emit without discarding valid siblings, and Artifact interpretation follows the declaration recursively through arrays rather than object shape. Required cases cover semantic text, strings, Enum, numeric, recursive array/tuple paths, trigger/action parity, and pin/restart evidence rederivation. |

| Id | Behavior |
| --- | --- |
| `node.sections` | A node body consists of config statements, cell declarations, an action graph, and child declarations. Direct cell declarations are harvested declaratively from anywhere in the node's outer statement list, are visible to actions that precede them in source, and have runtime slots before the action graph runs. Cell declarations nested inside the action graph are rejected at parse. |

| `cfg.display-metadata` | Display name and description parse into the IR as literals; non-literal shapes are rejected. |
| `cfg.guidance` | Authored guidance parses into the IR and reaches the host. |
| `cfg.forgetful-entry` | Defaults to false. When true, each new entry is forgetful: it discards the prior outcome and action frame while preserving cell values, child traversal outcomes, and canonical identity. During the entry, resolved actions remain remembered normally. |

Host params are carried on every judgment, observation, host-call, and instruction brief from the node. Instruction-level host params merge over node host params when both are objects, and postcheck work uses the merged value. ### Cells (`cell`)

| Id | Behavior |
| --- | --- |
| `cell.declaration-form` | Every declarator in a node-body declaration must use a supported Arc cell constructor. Every cell type uses call-form declaration syntax; a non-cell declarator and a `new` initializer are rejected, including when another declarator in the same statement is a valid cell. |
| `cell.enum` | Ordered string enum. Ordering uses ordinal position in one unambiguous declared values array, not lexicographic order. Equality and inequality use exact string values without requiring matching Enum declarations or literal membership. |
| `cell.enum-invalid` | An observation value outside the declared values is an invalid item: the item re-yields and the valid report subset applies. |
| `cell.bool` | True/false flag with typed writes and observations. |
| `cell.static-assignment-type` | Every cell and return write whose producer evidence and destination guarantee prove incompatibility is rejected; a one-time landing whose judgment is `unknown` is deferred and remains runtime-validated before mutation. String, number, and boolean carrier evidence is distinct from a site guarantee, Artifact and cursor expressions retain their provenance, and arrays recurse by element evidence. Enum membership, Index bounds, and other concrete refinements remain runtime checks. Required cases cover literals, typed reads, compound expressions, exact values, recursively compatible and incompatible arrays, and effects/return writes. |
| `cell.str` | Arbitrary plain string values via observation and via writes; a non-string observation result is an invalid item. |
| `cell.num` | `Num` is the one authored numeric cell. Stored values are finite JavaScript numbers; strict direct, whole-array, element, span-result, and return writes normalize negative zero, perform no mutation on non-finite poison, and do not consult `observeAs`. Fractions and finite values outside observation bounds are valid direct writes. Unset reads remain strict under the ordinary cell rules. |
| `cell.numeric-observation-spec` | `Num.observeAs` is declaration-only and has the exact `number` or `integer` shape with optional inclusive finite ordered bounds; integer bounds and reports use safe integers, with omitted bounds defaulting to safe extrema in metadata. It constrains observation reports only. `RangedInt(min, max, config?)` accepts ordered safe-integer bounds and desugars to integer-observed `Num`; direct writes therefore remain ordinary `Num` writes. Required cases cover both metadata variants, the intentional safe-integer tightening of `rangedInt` metadata, current values outside the spec, malformed specs, and out-of-spec report invalid items. |
| `cell.cursor` | Cursor cells accept only cursor values, are not observable (rejected at parse), and poison the traversal on a non-cursor runtime write. |
| `cell.is-unset` | `cell.isUnset()` is a zero-argument local boolean expression and a cell read. It is true only while a value cell or declared channel is unset, false for falsey values once set, and rejects unknown receivers. |
| `cell.artifact` | `Artifact()` is an unset value cell; `Artifact(path)` is the same cell initialized once on first entry from a string-valued expression. Document `ArtifactCell` IR carries only the optional constructor initializer; traversal storage separately holds an exact `ArtifactValue` or remains unset. Both forms follow the ordinary rules for typed writes, unset, channels, payloads, persistence, and unset consumers. Equality and inequality compare logical paths without coercion; ordering is rejected. In a value-position template an Artifact value contributes logical path text, while in semantic text it remains a structured Artifact part. `isUnset()` remains available without consuming the value. |
| `cell.artifact-template` | A string-valued path expression initializes once after args installation and before the body. Source-order initialization permits direct reads of string cells/channels and Artifact projection through a value template; later or otherwise unset dependencies fail under ordinary value-consumer rules. The complete result must be a non-empty relative path without dot segments, and later writes, reconstruction, or re-entry do not rerun or link the initializer. |
| `cell.observing` | The observation question may be defined once through declaration config or a later `observing` assignment; duplicate declaration keys, declaration-plus-assignment, and repeated assignments are parse errors. A per-call second argument to `observe` / `observeOrAsk` overrides the configured question for that call and flows into the observation brief. |
| `cell.bare-boolean` | A bare `Bool` cell in a boolean-evaluation position produces a lint warning because its unset value would poison the traversal. Direct branch and ternary tests, logical operands, negation operands, and boolean hook returns are covered, including when nested inside another value expression. Explicit equality and `cell.isUnset()` do not warn. A non-boolean value in the same position is a validation error, not a warning (see `cell.boolean-position`). |
| `cell.boolean-position` | A boolean position — an `if` test, a `&&`/`\|\|` or `!` operand, a ternary test, or a `this.trigger`/`this.catchDeflection`/`resolveWhen`/`deflectWhen` return — accepts only a boolean, without coercion. `&&`/`\|\|` are boolean operators: both operands are boolean positions wherever the expression appears, including a value position. Proven non-boolean evidence — a `Str`, `Num`, `Enum`, `Dialog.Cursor`, array value, typed array element, map span, or definitively declared host result, whether bare or a logical, negation, or ternary-test operand — is a registration error; a producer without evidence is admitted provisionally and raises at runtime if its value is non-boolean. An explicit comparison or `Num.isFinite(...)` is accepted, and a ternary's branches may be any type. |
| `cell.dead-read` | Reading an unset cell where a concrete value is required — a write value, host-call value argument, or template interpolation — is a runtime error that poisons the traversal. Comparisons may consume unset values: equality and ordering return false without coercion, except inequality returns true, whenever either operand is unset. Boolean evaluation rejects unset. Comparisons over not-yet-set cells can gate later work. Static analysis follows readable value declarations independently of observability. A cell read with no operation that can set it in scope is a `read-without-assignment` error, and a read ordered before the cell is set on the same path is a `read-before-assignment` notice. A completed declaration initializer, direct `$set`, observation of a direct target, `$enter`/`$enterLoop` `returns` binding, or `$map` `results` array sets a cell; a decorated element write instead reads its root. Array length, indexed reads, `$map` receivers, and decorated writes also read the root. Declaration identity preserves lexical shadowing. Every statement kind that carries an expression contributes its reads, `$map` included: the mapped receiver, callback body, and `span.result.$set(...)` values. Branch arms intersect and an invoke body walks inline, while a `$map` callback's own writes are not definite on the path, since an empty input runs it zero times. |
| `cell.array` | `Array(elementCell)` declares a one-level array cell whose element is one constructed scalar observable cell or zero-argument `Artifact()`. A scalar element may carry `observing` as the per-item question; an Artifact element carries no initializer or observation metadata and makes the array unobservable. A bare element constructor (`Array(Str)`), nested array, cursor, Index, invalid Artifact constructor, and extra arguments are rejected. Hand-built public IR follows the same guarantee and declaration-shape checks through `validate` and `Runtime.add`. Direct and decorated action targets normalize to `[root, ...accessors]`; dot access becomes a string-literal accessor, while access through a scalar or Artifact is invalid. |
| `cell.array-values` | Array cells take whole-value `$set`/`$unset`; an existing element is a synthetic element-spec target for `$set`, while element `$unset` is rejected. A whole-array write validates every element atomically and an element write validates and deep-clones the replacement and root list while preserving siblings. Scalar and Artifact element specs use the same write pipeline. Equality and inequality require one shared scalar or Artifact element authority, recursively admit concrete elements under it, compare ordered values structurally under `expr.comparison`, and apply the shared unset-comparison rule. Primitive arrays interpolate through the numeric-emission guard before comma-joined JavaScript stringification; other arrays are not renderable. Ordering, arithmetic, boolean evaluation, and negation of a whole array are rejected statically. |
| `cell.array-read` | `items[index]` is a sigil-less element-value read and `items.length` a sigil-less non-negative-safe-integer read, on a lexical array cell or typed array channel. An indexed read retains the declared element guarantee. Reading an element or length of an unset array poisons; indexing or reading length of a non-array cell is a validation error. A decorated action target reads the root aggregate and accessor cells and does not count as initializing the root. |
| `cell.array-index` | Every array read and decorated target requires a non-negative safe integer before checking current bounds. Fractions, negatives, nonnumbers, non-finite values, and integers above JavaScript's `Number.MAX_SAFE_INTEGER` use `invalid-array-index`; a valid safe integer outside the array uses `array-index-out-of-range`. Local brief-free arithmetic is admitted in reads and every target operation (`items[i + 1]`); general host-backed arithmetic is rejected by the local expression stratum. `Index` return writes enforce the same refinement. |

### Action Forms (`act`)

| Id | Behavior |
| --- | --- |
| `act.set` | A typed write resolves its cell target before evaluating its value, writes either the whole root or one existing array element, then execution advances. Later statements observe the written value. Numeric targets apply `cell.num`: finite admission and negative-zero normalization happen before mutation, independently of observation metadata. |
| `act.unset` | A zero-argument clear resolves once reached, then execution advances. It accepts direct root targets and rejects arguments, decorated targets, and unknown cells. |
| `act.observe` | A resolved report writes the target leaf; an unknown report consumes the action and preserves any existing value; a prior write supplies the brief's current value but does not resolve the action. An element observation briefs a canonical concrete path with scalar metadata and the element question, then replaces only that element. Numeric validation and normalization are owned by `proto.observation-number-normalization`. |
| `act.observe-or-ask` | Resolves only on a concrete reported value; unknown and needs-user reports resurface the action on later briefs. |
| `act.observe-group` | A grouped `$observe({ a, b })` / `$observeOrAsk({ a, b })` binds cells by same-name binding (rename, computed key, spread, duplicate, empty, and a second argument are parse errors; unknown and non-observable cells are validation issues), emits one brief carrying a per-cell field with its own `observing` question and type metadata, and resolves from one report addressing every field: `resolved` fields are written together before execution continues, `unknown` fields are skipped, a report that omits a field or supplies a value failing the field's type is an invalid item that writes nothing and re-emits, and a grouped `$observeOrAsk` report with any `needs-user` field writes nothing and re-emits the whole group. An `Array` field carries `{ type: "array", element: {...} }` metadata and reports its whole list per `act.observe-array`. |
| `act.observe-array` | Observing a scalar-element array cell briefs the value as `{ type: "array", element: {...} }` with the element's `observing` as the per-item question; a resolved report supplies a complete element-typed list validated and normalized all-or-nothing (any bad element rejects the whole report as an invalid item that writes nothing and re-emits), and the runtime writes the whole array once before continuing. Whole, indexed, grouped, and observe-or-ask Artifact-array targets are rejected as non-observable and never enter observation protocol types. |
| `act.instruct` | One-shot instruction: its lap collects an application evidence and a `deflectWhen` evidence, each banked once settled, and it resolves when applied with deflect evidence false. A true deflect evidence short-circuits the lap honoring an application from up to the same handback — an applied one-shot stays resolved through the deflection, an unapplied one re-presents fresh after a catch or re-entry. Bare `proceed`, a fresh runtime start, and a rejected report re-yield it. Authored `resolveWhen` is rejected at parse. Instruction `hostParams` follow the direct/nested numeric-literal rules and diagnostic precedence in `doc.numeric-validity`. |
| `act.instruct-loop` | Sticky instruction: requires `resolveWhen` at parse. Each iteration is a lap collecting a `resolveWhen` evidence and a `deflectWhen` evidence, each banked once settled (across fresh runtimes) so later briefs re-pose only open checks. With both evidences in and no deflection, a true `resolveWhen` resolves the whole loop and a false one starts a fresh lap; a true deflect evidence short-circuits the lap honoring a banked `resolveWhen`. Application toggles the presentation to `postcheck` without gating the lap, and the current frontier phase persists. |
| `act.instruction-text` | Instruction text accepts string and template literals; value expressions and ternaries render to text; entity and Artifact mentions are preserved as semantic parts. Ordinary interpolation reports `invalid-template-interpolation` when interpolating an unset value and applies the distinct `semantic-template interpolation` finite-number consumer before string conversion. Artifact projection to path text is confined to value-position templates. |
| `act.instruction-literal` | Bare string and template expression statements are rejected as unsupported statements, through the same path as any other invalid statement. |
| `act.judge` | A semantic boolean check usable in every expression position: branch conditions, write values, and hook returns. It blocks until reported. The reported answer pins for the remainder of the SEG and a resumed walk replays it instead of re-asking. |
| `act.host-call` | An expression-position host call blocks until the host reports a value. Under definitive runtime analysis, its action path must resolve to an operation with a declared result; that result supplies producer evidence to every surrounding consumer. Exact arity and parameter coherence are checked at registration, and rendered arguments receive concrete admission before emission. An accepted sanitized and typed result, including explicit top-level unset, pins for the remainder of the SEG like a judgment. Artifact construction may consume a reported string only from a declared string producer; an Artifact result is interpreted under its declaration and validates an exact `{ path: string }` carrier. Artifact arguments retain their value shape, semantic template arguments retain structured Artifact parts under `SemanticText()`, and a path previously materialized as a string is passed as a plain string. Targets accept dot and static string-literal bracket segments; dynamic computed targets, `$`-prefixed value-call operations, and host calls inside another host call's arguments are rejected. Report transport sanitation is owned by `proto.host-call-result-sanitization`; declared result admission is owned by `runtime.host-module-spec`. |

### Control Flow (`flow`)

| Id | Behavior |
| --- | --- |
| `flow.if-else` | Branch conditions re-evaluate whenever the walk reaches them, routing on cell state, node state, semantic checks, and regex tests. |
| `flow.label-break` | Labels attach only to block statements and `break` must name a label (both parse rules). A labeled break unwinds through nested labels to its target, in the action graph, hook bodies, effects bodies, and invoke bodies (where labels are local). |
| `flow.unreached-branch` | Actions on an unreached branch keep their existing state and become the frontier when later state makes the branch reachable. |

### Invokes (`invoke`)

| Id | Behavior |
| --- | --- |
| `invoke.rerun` | The body executes on every fresh reach and is never memoized; its completion pin skips it during resume. |
| `invoke.continuation` | The enclosing SEG continues after a completed invocation. Body writes are visible to later statements while earlier evaluations remain pinned. |
| `invoke.convergence` | Under the experimental `writeDiffMode: "rewalk"` Node IR override, a body that never reaches a fixpoint poisons the traversal at the re-walk bound while an idempotent convergent body settles. Authored parsing selects `advance`, where a completed body pins its completion instead of re-walking (see `seg.experimental-rewalk`). |
| `invoke.blocked-resume` | A blocked body resumes the same invocation on the next report; a completed invocation's pinned completion keeps it skipped while resuming toward a later frontier, and a later sibling's report does not re-run it. |
| `invoke.dialect` | `invoke(() => { ... })` is a first-class statement whose attached body admits the full node-body action dialect — enter forms, instruction forms, and nested invokes — with body element ids scoped under the invoke's own id and an independent label scope. The statement-position IIFE form is a parse error pointing at `invoke`. |
| `invoke.rejections` | A missing or extra argument, parameters, the function-expression form, and `return` / declarations inside the body are rejected at parse; `invoke` is a reserved name for cells and nodes. |
| `invoke.scope` | The body shares the enclosing node's cell scope; writes — including from nested invokes and in-body enters — become visible to the enclosing graph. Body reads belong to the invoke's local read-set and, transitively, to every enclosing set. |
| `invoke.deflection` | A deflection from the body abandons the open invocation and routes to the enclosing node's catch; a child that catches its own deflection leaves the invocation open; an uncaught child deflection abandons the invocation as it crosses into the body. A caught deflection re-reaches a fresh invocation. |
| `invoke.refs` | In-body work carries the enclosing node's ref as source and active ref; in-body instructions inherit the enclosing node's effective `deflectWhen`, including nested. |
| `invoke.transitions` | Invoke runs never latch node transitions. |

### Map and Span (`map`)

| Id | Behavior |
| --- | --- |

### Composition (`compose`)

| Id | Behavior |
| --- | --- |
| `compose.children` | Owned children store traversal state inline under the parent and read outer cells lexically; lexically owned siblings attach to the lexical owner, not the immediate caller. |
| `compose.imports` | Imported arcs resolve by source then root identifier, keep fully isolated scope and their own lifecycle; completion bubbles back to the caller's enter and deflection propagates to the caller's catch. |

| `compose.enter` | Resolves when the target reaches covered or skipped; the caller suspends while the target is unresolved. | `compose.enter-loop` | Requires `resolveWhen` at parse. Staged returns commit only when the whole loop resolves. |
| `compose.newcopy` | A `newcopy` target creates a blank anonymous copy per call — for children and imports — stored under its caller, never addressable through node-state reads. A completed copy is replaced on the next entry, while an unresolved copy resumes. |
| `compose.forgetful` | A `forgetful` target forces a forgetful entry of the canonical node: it preserves canonical identity, cell values, and child traversals; clears the prior outcome and action frame once at the entry boundary; re-evaluates the guard; and makes the entry's outcome the new reported state. | `compose.signature` | A node declares its typed channels with `args = { … }` / `returns = { … }` defaulted parameters whose values are constructed channel specs (`Bool`, `Str`, `Enum`, `Num`, `Artifact`, `Dialog.Cursor`, `Index`, `Array`). Channel specs never carry `observeAs`; `Artifact()` is zero-argument both as a scalar and as the immediate element of `Array(Artifact())`, while nested channel arrays remain invalid. Both parameters are optional; when both are present `args` precedes `returns`, and no other parameter name is admitted. The parsed signature is public IR on the node. The old destructured `{ args, returns }` form is a parse error, and `Index()` cannot declare a cell. |
| `compose.args` | The args channel exposes caller-backed cells read-only under child-local keys declared in the signature, readable in the child's action flow and effects. Entries bind shorthand (`{ report }`) or renamed (`{ inputReport: report }`), so channel keys decouple from caller cell names, and one caller cell may back several args keys. `Runtime.enterArc` supplies the same declared channel by a cloned, schema-validated value rather than a caller-cell link. A key left unbound by the caller or by `enterArc` reads as unset (see `compose.unbound-channel`); a reference to a key the node does not declare poisons an entered traversal, while an undeclared or incompatible `enterArc` key is a synchronous pre-execution caller error. Non-literal channel objects and unknown caller cells are rejected at validation. Reading `args.<key>` into a `cell.$set(...)` of an incompatible type is a validation issue (at `parse` and `Runtime.add`), the same static check as `span.item`. |
| `compose.returns` | Return writes are valid only inside effects (rejected elsewhere at parse, including inside control flow), validate against the node's own declared returns spec, and stage cloned candidates rather than mutating caller cells. Entries bind shorthand or renamed, and a renamed entry commits through the child key into the bound caller cell using the same spec-aware write as authored `$set`. Binding one caller cell to more than one returns key is a parse error. Candidates commit on normal resolution only — not on skip or deflection — and keys the child never set leave caller cells unchanged. For a directly invoked root, the same transaction is exposed on a covered `TerminalBrief`: declared-but-unset returns produce `{}`, while a root without declared returns and every deflected or poisoned root omit `returns`. A write to a channel the node does not declare poisons the traversal. A `returns.<key>.$set(value)` whose value has an incompatible type is a validation issue (at `parse` and `Runtime.add`), the same static check as `span.result`, with runtime validation retained for dynamically produced values. |
| `compose.typed-binding` | An `$enter(...)` channel binding is checked directionally against the target's declared signature: an undeclared key and a provider spec not reusable by its receiver are errors. Same-document targets are checked during document analysis; imported targets are checked by atomic `Runtime.init` in either add order, and failure leaves the runtime collecting. Scalar type, enum members, dialog-cursor shape, and array element shape recursively must match; `Index` provides `Num`, while `Num` cannot provide `Index`. Args use the caller binding as provider and returns use the declared return channel as provider. An array-typed channel supports `channel[i]` / `channel.length` and is rejected in ordering/boolean positions; a non-array channel receiver is a validation error. Typed values cross matching returns channels and commit into compatible caller cells. |
| `compose.unbound-channel` | A channel a node declares but the caller leaves unbound is legal on both sides: a declared-unbound args read is unset and `isUnset()` is true, a declared-unbound return stages locally and is discarded at resolution with no caller commit, and a read-set snapshot records it as resolved-unset rather than an unresolved read. A caller forwards its own typed `args.*` into a child via an args projection (`args: { key: args.other }`), including passing an unbound projection through as unset. |
